sessions and sign-in

this guide covers how senro remembers a visitor between requests, how the guestbook makes accounts and signs people in, what senro does to keep a password safe, and how it limits sign-in attempts and asks for a signed-in visitor.

the session

a session is a map of strings the browser keeps in a cookie and sends back with each request. the cookie holds the map as JSON beside an HMAC-SHA-256 of it under the app's secret, so a session the browser altered, or one another app signed, reads as an empty map. an action reads it with web/session req secret and keeps a changed one by answering web/kept response secret session. the guestbook carries its notices this way: an action puts a flash in the session before it redirects, and the page that shows the notice clears it.

web/signed_in req response secret session id keeps the session with id as its viewer, and web/viewer req secret reads the viewer back, or "" for a visitor who has not signed in. a sign-in lasts web/session_days, fourteen. the server stamps each request with the time it arrived, and a request later than that reads the session without its viewer; whatever else it keeps survives.

making an account

an account is a model like any other. its create action checks the form with rules before it does any expensive work, so a sign-up that cannot succeed costs no hashing.

examples/guestbook/accounts.kso
import "../../models"
import "../../passwords"
import "../../pg"
import "../../web"
import "./entries"
import "./views"
import "std/text"

# An account, as the `accounts` table stores it: the name its holder signs
# with, and a digest of the password. The password itself is never stored.
pub type account
  id
  name
  digest

# Anyone may make an account.
pub without_sign_in = ["create" "new"]

pub fn create? _ _
  true

pub fn new req _
  effect (opened req "" {} 200)

# An account needs a name nobody holds and a password of eight characters or
# more. The name is looked up before the password is stretched, so a sign-up
# that cannot succeed costs no hashing.
pub fn create req db
  f = web/form req.body
  name = text/trim (web/value f "name")
  password = web/value f "password"
  pg/query db held [name] .> (r -> joined req db name password r.rows)

held = "select id from accounts where name = $1"

fn joined req db name password rows
  short = "Use eight characters or more."
  found = models/problems [
    (models/rule "name" (name == "") "Choose a name.")
    (models/rule "name" (length rows > 0) "That name is taken.")
    (models/rule "password" (length password < 8) short)
  ]
  return effect (opened req name found 422) if models/problems? found
  passwords/digested password
    .> (d -> models/created "" db account_model { "digest":d "name":name })
    .> (w -> made req w)

fn made req kept:account
  s = web/session req entries/secret
  welcomed = put s "flash" "Welcome, {kept.name}. Your account is made."
  home = web/redirect "/"
  effect (web/signed_in req home entries/secret welcomed kept.name)

fn made _ _
  effect web/denied

# The sign-up form shows the name as typed and the problem with each field,
# if any. A password is never sent back.
fn opened req name problems code
  heading = "Make an account"
  page = views/door_view heading "/accounts" "Make it" name problems
  framed = views/layout_view "Make an account · Guestbook" page
  views/answer_as req code framed

the password is never stored. passwords/digested stretches it with PBKDF2-SHA-256 under a sixteen-byte salt from the operating system's secure source and answers text that names everything a later check needs:

the stored digest
pbkdf2-sha256$<rounds>$<salt, base64>$<digest, base64>

because each digest names its own rounds, the default can rise without breaking the digests already kept. it is 100,000 rounds, a sixth of what OWASP asks, because a release build of kanso stretches 100,000 in about a fifth of a second and the full count would hold a sign-in for more than a second. SENRO_PASSWORD_ROUNDS lowers it for development, where the development tier is fourteen times slower.

signing in

the session is a singular resource: session/new is the form, session/create signs in, and session/destroy signs out.

examples/guestbook/session.kso
import "../../models"
import "../../passwords"
import "../../pg"
import "../../web"
import "./entries"
import "./views"
import "std/text"

# One address may try to sign in ten times in three minutes, as Rails 8's
# generated sessions controller allows. Past that, `over_limit` answers the
# sign-in page again, saying why.
pub rate_limits = { "create":"10 per 3 minutes" }

pub without_sign_in = ["create" "new"]

# Signing in and out. The session is the signed cookie `web` keeps, and
# signing in writes the account's name into it as the viewer.
pub fn new req _
  effect (opened req "" {} 200)

# A name with no account is checked against nothing at the same cost, so a
# refusal takes as long whether or not the name exists, and the answer is
# the same: a name and a password that do not match.
pub fn create req db
  f = web/form req.body
  name = text/trim (web/value f "name")
  password = web/value f "password"
  pg/query db digest_of [name]
    .> (r -> kept_digest r.rows)
    .> (kept -> entered req name kept password)

digest_of = "select digest from accounts where name = $1"

fn kept_digest rows
  return passwords/stand_in if length rows == 0
  effect (models/cell rows[1] "digest")

fn entered req name kept password
  return refused req name if not passwords/matches? password kept
  s = web/session req entries/secret
  back = web/return_to req entries/secret "/"
  welcomed = put (delete s "return_to") "flash" "Signed in as {name}."
  home = web/redirect back
  effect (web/signed_in req home entries/secret welcomed name)

fn refused req name
  wrong = { "password":"That name and password do not match." }
  effect (opened req name wrong 422)

pub fn over_limit req
  wait = { "password":"Too many tries. Try again in a few minutes." }
  effect (opened req "" wait 429)

# Signing out keeps the rest of the session and forgets the viewer.
pub fn destroy req _
  s = delete (web/session req entries/secret) "viewer"
  r = web/redirect "/"
  effect (web/kept r entries/secret (put s "flash" "Signed out."))

fn opened req name problems code
  page = views/door_view "Sign in" "/session" "Sign in" name problems
  views/answer_as req code (views/layout_view "Sign in · Guestbook" page)

two details keep a refusal from saying more than it should. a name with no account is checked against passwords/stand_in, a digest no password matches, at the same rounds, so a refusal takes as long whether or not the name exists. and passwords/matches? compares the two digests over every byte, whichever differs first, so the time a refusal takes says nothing about how much of a guess was right. the answer is the same in both cases: a name and a password that do not match.

too many tries

a module limits how often one client may call an action by naming it in rate_limits, with a count per a window of seconds, minutes, hours or days. the guestbook's session module allows ten sign-in attempts in three minutes. senro tells clients apart by the address at the other end of the connection, which kanso's net/peer reads, and keeps the times of each client's calls to each limited action in the server's memory. a restart clears them, and two servers count separately.

a call past its limit is answered by the module's over_limit when it has one, and by a bare 429 when it does not. the guestbook's shows the sign-in form again, with a 429 and a line asking the visitor to wait. a name in rate_limits that is not an action of the module, or a limit senro cannot read, is refused when the app compiles:

kanso check
error[derive]: `5 a minute` is not a count per a window, such as "10 per 3 minutes"
  --> ./door.kso:1:5
   1 | pub rate_limits = { "create":"5 a minute" }
           ^

pages that ask for a sign-in

every action asks for a signed-in visitor unless its module names it in without_sign_in, as devise's authenticate_user! does for a Rails controller. the guestbook opens its home page, its list of entries, and the forms for making an account and signing in; writing an entry needs a signed-in visitor, and its action no longer checks for one itself. the entry asks for this once, when it serves its routes:

examples/guestbook/main.kso
import "../../kata"
import "../../models"
import "../../pg"
import "../../routes"
import "../../web"
import "./accounts"
import "./entries"
import "./home"
import "./migrations"
import "./removal"
import "./session"
import "./signatures"
import "./views"

signed = web/requiring_sign_in routes entries/secret

web/requiring_sign_in routes secret wraps every action that is not open. a visitor who has not signed in is sent to /session/new, and on a GET the path they asked for is kept in the session as return_to. once the password matches, session/create sends them back there with web/return_to req secret fallback, which answers the fallback when nothing was kept. a name in without_sign_in that is not an action of the module is refused when the app compiles.
