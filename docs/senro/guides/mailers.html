mailers

an app's mail is written in mailer modules, as a Rails app keeps it in mailers. a module whose name ends in _mailer holds one function to a letter. an action calls the function, the letter is queued, and a worker beside the server sends it. this guide covers writing a letter, the links it carries, how it is sent, and how to read mail in development.

a mailer

senro generate mailer account welcome password_changed writes account_mailer.kso with a letter for each name after the mailer's.

what the generator wrote
import "<senro>/mail"
import "std/text"

# The app's account mail, as a Rails mailer holds it: what each
# letter says. Each is queued on `db` and sent by the worker beside the
# server.
#
# The address the app's mail comes from. Change it to one the mail
# server `SENRO_MAIL` names will send as.
sender = "noreply@example.com"

pub fn welcome db to
  mail/delivered_later db (welcome_letter to)

fn welcome_letter to
  lines = [
    "Hello,"
    ""
    "Write what this letter says here, one line of it to a string."
  ]
  body = text/join lines "\n"
  mail/composed sender to "Welcome" body

pub fn password_changed db to
  mail/delivered_later db (password_changed_letter to)

fn password_changed_letter to
  lines = [
    "Hello,"
    ""
    "Write what this letter says here, one line of it to a string."
  ]
  body = text/join lines "\n"
  mail/composed sender to "Password changed" body

the first import is written with the app's own path to senro, shown here as <senro>. each letter is two functions. the pub one is what an action calls, with the database session and the address to write to. the private one says what the letter holds. mail/composed from to subject body makes the message: plain text from one address to one address. an address is bare, ana@example.com, or follows a name, Ana <ana@example.com>.

the routing convention leaves a mailer alone. its pub functions are called by actions in other modules, and none of them answers a request.

a letter with a link

most of an app's mail exists to carry a link: confirm this address, choose a new password. the mailer that senro generate authentication writes, account_mailer, sends three such letters: a reset, a confirmation and an unlock. the reset is shown here.

examples/notebook/account_mailer.kso
# The app's mail, as a Rails mailer holds it: what each letter says, and
# the signed link it carries, which starts with `mail/url_for`. Each letter
# is queued on `db` and sent by the worker beside the server.
#
# The address the app's mail comes from. Change it to one the mail server
# `SENRO_MAIL` names will send as.
sender = "noreply@example.com"

# A link to choose a new password, bound to the digest the account keeps,
# so it works once.
pub fn reset req db id email kept
  time/now
    .> (t -> mail/url_for (reset_path req id kept t))
    .> (link -> mail/delivered_later db (reset_letter email link))

# The page the link opens, with the token in its path.
fn reset_path req id kept t
  token = tokens/made "reset" req id kept t passwords/reset_minutes
  routes/path_to "resets/edit" token

fn reset_letter email link
  lines = [
    "Someone asked to reset the password of your account."
    ""
    "Choose a new one here, within fifteen minutes:"
    ""
    link
    ""
    "If it was not you, there is nothing to do: your password is unchanged."
  ]
  mail/composed sender email "Reset your password" (text/join lines "\n")

mail/url_for path is the address of a path on the app's own site. it reads the site from the SENRO_URL environment variable, such as https://notebook.example, and uses http://127.0.0.1:3000 when that is unset, which is where a development server listens. it never reads the site from the request's Host header. whoever sends a request chooses that header, so a link built from it could carry a reset token to a site of theirs.

the token in the path is made by tokens/made for the purpose reset: it is signed with the app's secret, which the request carries, and it expires. the confirmation and unlock letters take theirs from accounts/confirm_token and accounts/unlock_token, which bind each to what the link changes, so it works once, and give it a day. sessions and sign-in covers how one is made and checked.

sending now, and sending later

mail/delivered message sends a message during the request and answers the text it sent. mail/delivered_later db message writes it to the jobs table instead, as Action Mailer's deliver_later does, and the request answers without waiting on a mail server. the entry senro new writes runs a worker on the mail queue beside the server, and that worker sends each letter a moment later. a letter whose delivery fails is tried again, as any job is. background jobs covers the table and the worker.

mail/mail.kso
# Queues `m` on the `mail` queue of the jobs table, so the request that asked
# for it answers without waiting on the mail server, as Action Mailer's
# `deliver_later` does. A worker running `mail/performers` sends it the way
# `delivered` does. A message `delivered` would refuse is refused here, before
# it is queued.
pub fn delivered_later db m
  why = refusal m
  return err why if why != ""
  fields = { "body":m.body "from":m.from "subject":m.subject "to":m.to }
  time/now .> (t -> jobs/later db "mail" "deliver" fields t)

it refuses a letter delivered would refuse before anything is written, so a bad address fails the request that asked for it and never waits in the queue.

the generated letters all use delivered_later. an action that queues one has usually just written something, and it should answer whether or not the mail server is up.

where mail goes

the SENRO_MAIL environment variable says how mail leaves the app.

SENRO_MAIL
unset or ""                    standard error, for development
dir:<path>                     a file of its own under <path>
smtp://user:pass@host:587      SMTP, after STARTTLS
smtps://user:pass@host:465     SMTP inside TLS from the first byte
smtp+insecure://host:1025      SMTP in the clear, for a mail catcher

the name and password in an SMTP address are optional and percent-encoded, as in any URL, so an address used as a name is written me%40example.com.

smtp:// refuses a server that does not offer STARTTLS. the alternative is sending in the clear, and a reset link read off the wire is as good as a password. the conversation ends before the sender or the recipient is named.

smtp:// to a server with no STARTTLS
C: EHLO guestbook.test
C: QUIT
not sent: err "the mail server at 127.0.0.1 offers no STARTTLS, and smtp:// sends only through TLS"

what a message looks like

with SENRO_MAIL unset, each message is written to standard error as it would go on the wire, so a developer reads the app's mail in the terminal the server runs in and follows the link from there.

a message on standard error
Date: Mon, 26 Oct 2026 07:33:20 +0000
From: Guestbook <noreply@guestbook.test>
To: ana@example.com
Subject: Reset your password
Message-ID: <spec@guestbook.test>
MIME-Version: 1.0
Content-Type: text/plain; charset=utf-8
Content-Transfer-Encoding: 7bit

Follow this link:
.
https://guestbook.test/r/1

a subject that is not ASCII travels as RFC 2047 encoded words, and a body that is not ASCII, or holds a line longer than SMTP allows, travels as base64. the mailer writes ordinary text and the mail module chooses the encoding.

dir:<path> writes each message to a file of its own under the path. senro's specs read mail that way: they drive an app over HTTP, wait for the file addressed to the account they made, and follow the link inside it.

what is refused

a message is checked before it is sent or queued.

mail/mail.kso
# What is wrong with a message, or "" when nothing is. A header holding a line
# break would let whoever wrote it add headers of their own, so it is refused
# before anything is sent.
pub fn refusal m
  return "mail needs a From address with an @" if not addressed? m.from
  return "mail needs a To address with an @" if not addressed? m.to
  return "a mail header cannot hold a line break" if broken? m
  ""

the line-break rule is about forms. a subject or an address that came from a visitor could hold a line break followed by a header of the visitor's choosing, such as a Bcc. a header with a line break in it is refused, so nothing a visitor types can add one.
