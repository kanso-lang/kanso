# Programs the wasm engine cannot run, and the text it answers instead.
# Read by both harnesses — tests/wasm_engine.rs under an embedded interpreter
# and scripts/browser_differential_run under headless Chrome — so a gap is
# stated once. A program listed here that starts passing is an error in both,
# because a gap that closed and stayed written down is a lie about the engine.
# A paragraph describing a gap whose lines are gone is the same lie, slower to
# catch, so an explanation leaves with the entry it explains.
#
# <path from the repo root><tab><substring the wasm engine answers>

# A page has no filesystem, so a program that lists a directory cannot run
# there. The capability is missing, not the agreement: `exists` still answers
# (false, for everything), and every other engine matches.
tests/golden/micro/dir_listing_is_sorted.kso	the playground has no filesystem

# A tab cannot start a process, so a program that runs one cannot run there.
# The capability is missing, not the agreement — the playground says so by
# name, which is what the differential law asks of an engine that declines.
tests/golden/micro/a_command_that_answers_127.kso	the playground cannot start processes
tests/golden/micro/process_run.kso	the playground cannot start processes
tests/golden/runtime/run_cannot_start.kso	the playground cannot start processes

# The same missing filesystem, on the read side: a page cannot open a file to
# find it absent, so it says why rather than reporting the absence.
tests/golden/runtime/read_missing_file.kso	the playground has no filesystem

# `is_dir` reads false in a page for the same reason `exists` does — there is
# no filesystem to ask — so the golden's first answer differs there.
tests/golden/micro/is_dir.kso	false
tests/golden/micro/make_dir_is_idempotent.kso	the playground has no filesystem
