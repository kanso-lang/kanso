# Programs the wasm engine cannot run, and the text it answers instead.
# Read by both harnesses — tests/wasm_engine.rs under an embedded interpreter
# and scripts/browser_differential.py under headless Chrome — so a gap is
# stated once. A program listed here that starts passing is an error in both,
# because a gap that closed and stayed written down is a lie about the engine.
#
# <path from the repo root><tab><substring the wasm engine answers>

# A page has no filesystem, so a program that lists a directory cannot run
# there. The capability is missing, not the agreement: `exists` still answers
# (false, for everything), and every other engine matches.
tests/golden/micro/dir_listing_is_sorted.kso	the playground has no filesystem

# A tab cannot start a process, so a program that runs one cannot run there.
# The capability is missing, not the agreement — the playground says so by
# name, which is what the differential law asks of an engine that declines.
tests/golden/micro/a_command_that_answers_127.kso	the playground cannot start processes
tests/golden/micro/process_run.kso	the playground cannot start processes
tests/golden/runtime/run_cannot_start.kso	the playground cannot start processes

# The same missing filesystem, on the read side: a page cannot open a file to
# find it absent, so it says why rather than reporting the absence.
tests/golden/runtime/read_missing_file.kso	the playground has no filesystem

# `is_dir` reads false in a page for the same reason `exists` does — there is
# no filesystem to ask — so the golden's first answer differs there.
tests/golden/micro/is_dir.kso	false
tests/golden/micro/make_dir_is_idempotent.kso	the playground has no filesystem

# A constant that names itself defers the mention, and the three engines hold
# that deferral differently: native and the oracle keep a cell nobody has
# demanded and say `<thunk>`, where the browser keeps the closure that would
# answer it and says `<fn>`. Both are honest about having no value yet; they
# do not use the same word for it. Closing this means teaching the renderer to
# ask a deferral what it is, which reaches into the interpreter's own render.
tests/golden/micro/a_constant_that_holds_itself.kso	<fn>

# The guarded shape that cannot be tied: `x = (cell x).v`. Native and the
# oracle refuse with "a lazy binding demands its own value" — the demand for x
# arrives while x's right-hand side is running, from a cell that has produced
# nothing. The browser has no blackhole to reach, so it follows the deferral
# round and round until the stack ends the program.
#
# Both engines say the program is wrong. Only one says why. This closes with
# the same work as the entry above: give the browser the blackhole the
# interpreter keys by name.
tests/golden/runtime/a_guarded_shape_that_is_not_a_knot.kso	the program ran out of stack: recursion went deeper than the stack holds

# Two constants naming each other. All three engines tie the knot and agree
# on the values it holds — `2 1` here. They part on how a deferral RENDERS:
# the browser keeps the closure that would answer the field and says `<fn>`,
# where native and the oracle hold a cell and print the record behind it.
#
# The same difference as a_constant_that_holds_itself above, and it closes
# with gavel 20b's render-forcing rather than with a blackhole: the browser
# has a deferral here, it just prints the wrapper instead of asking it.
tests/golden/micro/a_knot_through_two_names.kso	2 1 a_knot_through_two_names/node 2 <fn>

# A constant naming itself as a MAP value. The browser defers a list element
# and a constructor field but not a map value, so the mention is taken now
# and the ring has no floor.
#
# Deferring it there was tried and is worse: the browser then builds the
# cyclic map and renders it without a cycle guard, which overflows the HOST
# rather than the guest — a clean diagnostic traded for an abort. The value
# side and the render side have to land together, and the render side is the
# same work as the two entries above.
tests/golden/micro/a_knot_through_a_map_value.kso	the program ran out of stack: recursion went deeper than the stack holds
