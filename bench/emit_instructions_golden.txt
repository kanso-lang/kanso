# What the compiler spends emitting, counted at the frame that does it:
# `kanso::codegen::emit_ir` inclusive, over `kanso build pkg/codegen_corpus`
# in the staged box, read by scripts/gates/emit_instructions.sh.
#
# The three `kanso check` rows stop before codegen. The two codegen rows count
# the child tree (the clang driver, the convention probe's clang, `clang -cc1`
# and `ld`) and exclude kanso's own process, because it waits for a child and
# a loop whose iteration count belongs to the scheduler is external state.
# This row is the work between them: the frame is about 93% of what kanso's
# own process spends on a release build, so the codegen rows' exclusion drops
# the wait and little else.
#
# The anchor is exact: repeat the command from a freshly staged box and the
# frame reads the same to the instruction while the process around it moves.
# That is why the row is one command and not a family of them.
#
# Any change to the emitter moves it, and so does a change to the program it
# emits, since pkg/codegen_corpus is the subject. A change under lib/ moves it
# too, because lib/*.kso is `include_str!`'d into the compiler. Only CI's
# numbers are recorded; scripts/gates/measured_on.sh refuses other hosts.
#
# A rise is a regression to explain and a fall is a win to bank: say which in
# design/compiler-log.md, which holds the history of every move.
# measured-on glibc=2.39-0ubuntu8.9 rustc=1.98.1
