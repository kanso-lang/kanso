# The CPU features glibc's ifunc resolvers read when they pick memcpy, memcmp,
# strlen and their neighbours, as ld.so reports them. Sorted, so a diff reads
# line by line. The instruction gates consult this ONLY when a row has moved —
# it never refuses on its own.
#
# WHY IT IS HERE. `scripts/gates/dispatch.sh` has carried a `differs` verb
# since the day it was written and there has been nothing for it to compare
# against, so it answered "cannot tell" every time and no gate called it. The
# gates call `dispatch.sh name`, which prints the family and the model and
# stops. Family and model are the two rows a reader is most likely to find
# equal.
#
# WHAT A SWEEP OF THE JOB LOGS SAYS, 2026-09-17. Ninety-odd cost-goldens jobs
# printed this block (the `name` verb prints it whenever no block is recorded).
# Within any one job every printing is identical. Across jobs there are SEVEN
# distinct blocks, differing in 57 rows, and among them the basic family takes
# three values: 0x19, 0x1a and 0x6. The last is Intel. Level-3 cache spans
# 32 MB to 480 MB, and `Fast_Unaligned_Load`, `Prefer_No_AVX512` and
# `Prefer_PMINUB_for_stringop` — three of the switches those resolvers read —
# flip between them.
#
# The gates pin the cache-derived thresholds through GLIBC_TUNABLES, which is
# why the rows are as steady as they are. What the tunables do not reach is
# which implementation the resolver picks, and that is what this block is for.
#
# THE ROWS BELOW are from the cost-goldens job of kanso#1492 on e29fac05,
# chosen because on that silicon the three `kanso check` rows and the start-up
# row read main's goldens to the instruction. It is the silicon those values
# belong to.
#
# kq has done this since its own instruction vein opened; kanso had the reader
# and never the block.
