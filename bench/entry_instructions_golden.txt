# Retired instructions for `kanso check entry_corpus/main.kso`, counted under
# callgrind and anchored at `kanso::main` inclusive.
#
# `kanso check` routes a file by its content. A file with a top-level
# expression is an entry and goes through compile_parsed_entry, which merges
# the imports itself and runs its own whole-program check. Every `kanso run`
# takes that path. bench/compile_instructions_golden.txt counts a directory,
# which is a module, and bench/library_instructions_golden.txt counts a file of
# definitions alone. The rows move together for work in the shared front end
# and apart for the passes only one path runs; when they disagree in sign, the
# change landed on the path that moved.
#
# The rules this row shares with the module row are stated in that row's
# header: the seedless hash, the box at a fixed path, one row holding one
# value, the toolchain on the last line, the row taken from CI.
#
# EXCLUDED, because it cannot be normalized: `std::io::stdio::_print`
# inclusive, the one line `kanso check` prints when it finishes. Its cost
# moves with the binary's layout. The corpus is a single file, so no
# directory is read and the module row's second exclusion does not arise. The
# gate subtracts the subtree and prints it as a notice.
#
# A rise is a regression to explain and a fall is a win to bank: say which in
# design/compiler-log.md, which holds the history of every move.
