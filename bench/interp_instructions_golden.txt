# What an interpreted run costs, counted rather than timed.
#
# `kanso run --interp` on bench/interp_corpus, anchored at
# `run_interpreted_on_stack`, the entry of the thread the interpreter runs on.
# `kanso run --interp` pins a one-gigabyte stack and hands the program to a
# thread of its own, so `kanso::main` would see the front end and almost none
# of the run. The anchor leaves the front end out: a front-end change can move
# this row only by moving the binary.
#
# EXCLUDED: the printed line. The corpus prints what it decoded, and the
# `std::io::stdio::_print` subtree that writes it (LineWriter's memrchr over
# the formatted bytes) moves with the binary's layout rather than with
# anything the interpreter does: two builds of identical compiler source drew
# counts thirteen apart there. The gate prints that subtree's cost as a notice
# and subtracts it.
#
# The corpus builds its own input, interpolating a document of 220 objects
# and decoding it six times, so the workload is a property of the corpus
# alone and does not move when bench/large.json does.
#
# The interpreter hashes with the compiler's seedless hash. std's RandomState
# drew a fresh key on every process, and two runs of one binary read three
# million apart.
#
# This is the interpreter-speed term of the welfare objective. The row belongs
# to the rustc that built the compiler and the libc that serves it, both named
# on the measured-on line, and only CI's reading is recorded.
#
# A rise is a regression to explain and a fall is a win to bank: say which in
# design/compiler-log.md, which holds the history of every move.
# measured-on glibc=2.39-0ubuntu8.9 rustc=1.98.1
