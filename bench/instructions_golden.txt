# Retired instructions per benchmark, counted under callgrind. This is the
# work a process does, and it is the dimension every other vein here is blind
# to: allocation counters say how often the allocator was called, the emitted
# golden says how many lines the compiler wrote, the text golden says how big
# the machine code is. None of them counts an instruction.
#
# It exists because between 2026-07-27 and 2026-08-07 the decoder went
# 2,545,249,871 instructions to 2,762,364,162 — eight and a half per cent,
# matching the wall-clock regression almost exactly — with every allocation
# counter byte-identical the whole way. The chart called two of its lines
# "run speed" and "compile speed" and neither counted an instruction, so
# nothing anywhere could see it.
#
# Exact, not a band. Three consecutive runs give the same digits, because
# callgrind counts rather than samples and no other process can reach it. A
# rise is a regression to explain and a fall is a win to bank.
#
# Measured with an empty environment (env -i). The kernel copies the
# environment block onto the new process's stack and libc walks it before
# main, so a run id that gained a digit reads as fourteen instructions of work
# nobody wrote. With it pinned, two runs of unchanged code agree to the digit.
#
# These rows belong to the linux runner's compiler, and they belong to it more
# tightly than any other vein here: the same sources measured under Debian's
# clang read 2,762,364,313 for the decoder against ubuntu's 3,266,971,711,
# eighteen per cent apart, where the machine-code size of the same two builds
# differs by well under one. Instruction count is what an optimiser's inlining
# choices move most. So a toolchain bump will look like an enormous regression
# here and will not be one — regenerate every row in one go and say so in
# design/compiler-log.md, and never read a row against a number measured
# somewhere else.
#
# 2026-08-12 (later): basket 56,597,311 to 56,597,316, the other three unmoved.
# Five instructions, and they are the compare that stops `k_b_str_builder`
# re-seeding a header with room to spare. That guard takes an accumulator handed
# through one intermediate function from 752,908,406 instructions to 16,519,843
# at eight thousand appends. Five here.
#
# 2026-08-12 (later still): basket 56,597,316 back to 56,597,311, the same five.
# The guard is withdrawn — spare capacity is not sole ownership, and a builder
# that trusts it writes into a buffer somebody else holds, which took two
# rewritten panels of a book chapter to 88 GB. The 752,908,406 figure above is
# withdrawn with it rather than disproven: nothing re-measured it against the
# shape that matters.
# 2026-08-13: basket 56,597,311 to 55,987,313, a fall of 609,998 and 1.08%.
# jsonbench +5 and oneshot +10 are noise; encodebench rises 4,414. An accumulator
# handed round a cycle is no longer re-seeded on every hop, and seeding copies the
# whole string, so the work removed is larger than the carry's new flag and
# branches cost. The allocation counters for all four benchmarks are unmoved —
# this is the same work done without the copies.
# 2026-08-13 (later): every row falls, and so does every .text size. k_str_alloc
# is made inline: jsonbench -12,714,499 (0.41%), encodebench -22,032,496 (0.24%),
# oneshot -139,649 (0.22%), basket -169,500 (0.30%). The caller attribution that
# found this predicted about twenty million on the decoder against the twelve and
# a half measured, so it pointed at the right function and oversold the size —
# attribution counts what a function was charged, not what removing it returns.

# 2026-08-13 (last): jsonbench -815, encodebench +247, oneshot +247, basket
# -690, all under a thousandth of a per cent. net/port adds a function to the
# runtime object that none of these four call; what moves is the layout around
# it. Recorded rather than waved at, because a number that changes without a
# sentence is the thing this file exists to catch.
# 2026-08-14: a fifth row, and it is the largest number in this file by a
# factor of one and a half over the decoder — for a hundred and fifty
# kilobytes of input against jsonbench's several megabytes. That is the whole
# reason the benchmark exists: the work is quadratic in the array's length,
# and every counter in bench/cost_golden_wide.txt holds still while it grows,
# because the check that does the work allocates nothing.
# 2026-08-14: basket rises 405 instructions for the getter group's forcing
# no-match path and 16,082 for join's forcing, three hundredths of a per cent
# between them. widebench's row above predates both, so the runner has the last
# word on it.
# 2026-08-14: basket rises 405 instructions, four millionths. That is the
# getter group's no-match path forcing its value instead of exiting — the cost
# is the branch, paid where a getter is called and the arms miss. widebench's
# row above was measured before that landed, so the runner has the last word
# on it.
# 2026-08-14: widebench 15,730,176,374 to 134,061,218 — a hundred and seventeen
# times, and quadratic to linear. A list whose slots all lie below the outermost
# beat mark outlives every rewind, so its survival verdict cannot change and is
# worth keeping; the check used to walk all twenty thousand elements once per
# element printed. encodebench pays 404,830 (0.0044%) and basket 104,033 (0.19%)
# for the hash probe that keeps it, and jsonbench and oneshot do not move. That
# is the trade, stated: two programs give up a fifth of a per cent so that wide
# documents stop being unusable.
# 2026-08-14 (later): the carry tenures a value that has lived a lap, so the
# document threaded through a streaming loop is copied once instead of once
# per element. widebench's row is not comparable with the one above it — the
# fixture moves from twenty thousand elements to sixteen thousand, because
# above 16,384 the survivor-ratio guard refuses the evacuation and keeps the
# region, so a fixture on that side of the line exercises none of this. On the
# new fixture the unfixed compiler runs 11,627,314,301 instructions against
# 130,337,917 here, and takes 1.42 s against 0.00.
#
# The other four rise: jsonbench 0.10%, oneshot 3.44%, basket 2.59%,
# encodebench 5.49%. Ten variants were measured and encodebench read 5.49% in
# every one, including two isolations that removed the tenured answer and the
# shape of the walk separately. What is left is a branch in k_copy_alloc, the
# funnel every evacuated byte passes through, and a field in the struct that
# carries it — neither removable while tenuring exists. The trade is stated
# rather than hidden: the encoder pays five and a half per cent so that a wide
# document stops being quadratic.
# 2026-08-14 (last): the decoder does not move at all, encodebench by four,
# oneshot 36,186 and basket 42,026. Forcing inside to_int and split instead
# costs 1,273,192, of which 1,256,400 falls on the decoder alone because it
# calls to_int on every integer token. This is the correctness fix at the
# cheaper site: native and the oracle now agree where a computed string
# reaches either builtin.
# 2026-08-15: jsonbench +235, encodebench -202, oneshot -198, basket +180,
# widebench -180 — every row under a ten-thousandth of a per cent, and the
# signs disagree. The registration itself is one getenv and one signal call at
# startup; what moves each row differently is the layout around the handler
# the linker now places in every binary. Recorded rather than waved at.
# 2026-08-15: jsonbench +265,950 (0.0092%), widebench +16,000 (0.012%),
# oneshot +1,774, encodebench +400, basket +2. join and the utf8 zero-copy
# path now set the output string's cap, which they never did — the header
# comes from the bump allocator and held whatever was last in that slot. A
# zero cap sends k_str_chars down the walk, where a positive one sent it to a
# cached count that was never written, so what rises here is the walk that
# always should have run. The old numbers were cheaper and wrong.
# 2026-08-15: a sixth row, and the point of it. The cost deepbench prices
# allocates nothing — a survival memo keyed on a list pointer hits when one
# list is asked about repeatedly and misses when every iteration asks about a
# fresh one — so this vein and the machine-code one are the only two that can
# see it. No existing row moves.
# 2026-08-15: a step whose live value is small enough to be cheaper to leave
# than to stage is left where it is. widebench falls 32.5% and deepbench
# 69.3%; jsonbench, encodebench and oneshot each rise by NINE instructions and
# basket does not move. Nine is the branch itself, paid once per carry and
# invisible against billions — the three that rise carry no small steps to
# skip, so they pay the test and collect nothing.
#
# The numbers this replaces were measured against a compiler that could hand a
# scan a garbage length, and the run that produced them never finished. That
# was #907's uninitialised cap, not this policy.
# 2026-08-15: basket alone, 57,426,164 to 57,683,168 — 257,004 instructions,
# 0.45%. It is the one benchmark that grows an accumulator past its beat, so
# it is the one that pays the increment and the decrement; the other four do
# not move at all. That asymmetry is the counter working: it costs where the
# thing it counts happens.
