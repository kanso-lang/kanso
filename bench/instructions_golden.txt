# Retired instructions per benchmark, counted under callgrind. This is the
# work a process does, and it is the dimension every other vein here is blind
# to: allocation counters say how often the allocator was called, the emitted
# golden says how many lines the compiler wrote, the text golden says how big
# the machine code is. None of them counts an instruction.
#
# It exists because between 2026-07-27 and 2026-08-07 the decoder went
# 2,545,249,871 instructions to 2,762,364,162 — eight and a half per cent,
# matching the wall-clock regression almost exactly — with every allocation
# counter byte-identical the whole way. The chart called two of its lines
# "run speed" and "compile speed" and neither counted an instruction, so
# nothing anywhere could see it.
#
# Exact, not a band. Three consecutive runs give the same digits, because
# callgrind counts rather than samples and no other process can reach it. A
# rise is a regression to explain and a fall is a win to bank.
#
# Measured with an empty environment (env -i). The kernel copies the
# environment block onto the new process's stack and libc walks it before
# main, so a run id that gained a digit reads as fourteen instructions of work
# nobody wrote. With it pinned, two runs of unchanged code agree to the digit.
#
# These rows belong to the linux runner's compiler, and they belong to it more
# tightly than any other vein here: the same sources measured under Debian's
# clang read 2,762,364,313 for the decoder against ubuntu's 3,266,971,711,
# eighteen per cent apart, where the machine-code size of the same two builds
# differs by well under one. Instruction count is what an optimiser's inlining
# choices move most. So a toolchain bump will look like an enormous regression
# here and will not be one — regenerate every row in one go and say so in
# design/compiler-log.md, and never read a row against a number measured
# somewhere else.
#
# The line below is that rule, made checkable. The gate reads it, compares it
# against the host it is running on, and refuses to measure anywhere else —
# because the warning above did not stop this vein being regenerated from a
# container one glibc revision off the runner, whose rows sat about four
# hundred instructions low. Two ubuntu 24.04 boxes at 2.39-0ubuntu8.7 and
# 2.39-0ubuntu8.8 differ by more than most changes this vein is here to catch.
# measured-on glibc=2.39-0ubuntu8.8
#

# restarts at the front. basket carries the most of it because it sweeps text
# across beats; the five rows under a thousandth are the store itself.
#
# 2026-09-01 (later): nine rows fall and one rises. Two changes to the runtime,
# both about instructions the common path pays for the rare one.
#
# `k_die` and its eight siblings are noreturn and noinline now. Unmarked, clang
# inlined the fprintf and the exit into every runtime entry that validates a
# tag, so the entry built a frame and saved the registers that error path needs
# before it could test anything, on the path that never dies. That alone is
# digestbench -5.97%, deepbench -1.27%, escapebench -1.89%, pendbench -0.77%,
# widebench -0.48%, encodebench -1.27%, jsonbench -0.40%.
#
# And the one-byte append is straight-lined and outlined from the rest. Two
# thirds of the appends the encoder makes are a comma, a colon or a brace into
# spare capacity; the general path reaches its store through a pointer that is
# a phi of three predecessors, so a byte arriving in a register was written to
# a stack slot and read back. 47.3 instructions a call became 36 over 42.3M
# calls.
#
# widebench rises 0.13% and that is the split, not the noreturn: widebench
# appends strings, so every one of its appends now pays a call into
# k_b_append_wide. The alternative was measured — leave the byte case inline
# and outline nothing — and it costs widebench nothing and reads 74.47 against
# 74.50 on the objective, because it gives back 142M instructions on
# encodebench and 20M on jsonbench to save 384k on widebench. The model prefers
# the split, so the split is what shipped.
#
# 2026-09-01 (later still): every row falls and none rises. `k_ten_release`
# recomputed `k_ten_any` — a summary over all sixty-four beat depths — on every
# beat pop, including the pops where this depth held no block and the summary
# therefore could not have changed. k_beat_pop was 2,205,202 calls at 282
# instructions each in encodebench; 216 of the 282 were that walk. An early
# return when the depth is empty takes it to 66 a call and removes 476,323,632
# from encodebench, which is the whole of that row's fall to the instruction.
#
# encodebench falls to 7,393,828,977, oneshot to 40,210,572, deepbench to
# 705,254,951, escapebench to 248,370,445; jsonbench, basket, widebench,
# pendbench, indexbench and digestbench fall by less than a thousandth.
# 2026-09-01 (the ascii test): five rows fall, five do not move, none rises.
#
#   jsonbench    2,781,834,449 -> 2,747,404,799   -34,429,650   -1.238%
#   oneshot         40,210,971 ->     39,981,441      -229,530   -0.571%
#   widebench       64,077,249 ->     63,874,012      -203,237   -0.317%
#   basket          56,457,634 ->     56,449,207        -8,427   -0.015%
#   encodebench  7,393,829,376 ->  7,393,600,245      -229,131   -0.003%
#   deepbench, escapebench, pendbench, indexbench, digestbench identical
#
# k_utf8_bad's ascii test answers a run of seven bytes — the mean length it is
# handed — with two overlapping loads instead of a walk. The whole of
# jsonbench's fall is that function: 117,522,450 to 83,092,800.
#
# Every one of these five deltas is IDENTICAL to the one measured in the
# container on a Cascade Lake, against a runner on a Genoa. The absolute rows
# differ by a few hundred as they always do; the differences do not differ at
# all. That is what a change with no dispatch-sensitive path in it looks like,
# and it is the cleanest evidence this vein has produced that a delta can be
# read across silicon even when a row cannot.
# 2026-09-01: digestbench joins, at 152,573,619 retired instructions, measured
# by CI because this host's glibc differs from the one this file is pinned to.
# It is here because a benchmark counted on one axis and not the other is a
# trade nothing can see: every change that buys the digest's memory spends
# something in work, and this is where that something shows.
# 2026-09-01 (last): seven rows fall and three hold. jsonbench -1.045% and
# oneshot -0.481% are the map's initial pairs capacity going from four to
# eight, which halves the growth arm. deepbench -733, pendbench -2 and
# indexbench -370 are the tenure fix, which adds a branch to the beat pop and
# takes a free off it. encodebench -0.003% and basket -0.040% carry a little of
# both. Measured on CI's Genoa, family 0x19 model 0x11, the recorded silicon.
# 2026-09-02: six rows fall and four hold. The compiler now writes the
# dispatcher inline at every call site where the head is a value, so a fold
# whose callable is loop-invariant tests it once outside the loop instead of
# once a lap. digestbench -4.471%, pendbench -1.978%, encodebench -1.835%,
# oneshot -0.852%, deepbench -0.529%, basket -0.509%. jsonbench, widebench,
# escapebench and indexbench are byte-identical: they write such sites only in
# library folds their entries never reach, and the linker drops them. No
# allocation counter moves on any of the ten. Measured on CI's runner, family
# 0x6 model 0xad — NOT the recorded Genoa, and the deltas are large enough
# that the silicon does not explain them.
