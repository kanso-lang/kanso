# What the front end costs on bench/compile_corpus, the FIXED corpus the
# compile term reads since 2026-09-08. It was lib/json until that day, and
# the history below is written against that workload; why it moved is in the
# log entry for the day. lib/json is still most of what gets compiled here,
# since the corpus imports it, beside the std modules the ruling names.
#
# Rounds and visits say how much work the front end decided to do; peak bytes
# says how much it had to keep while deciding.
#
# The five samples in compile_golden.txt hold 126 visits between them, and
# nothing a compiler change does moves that number. This one moves.
#
# Rounds and visits are counts of the compiler's own algorithm, so they are the
# same everywhere and the gate diffs them on every host.
#
# Peak bytes is measured by the compiler's own allocator, so it belongs to the
# rustc that built it as surely as .text belongs to clang — a HashMap's growth
# schedule and a Vec's doubling are the standard library's. It used to be read
# against a two-per-cent band, and Clay ruled the band away on 2026-08-24: "that
# shouldn't be a tolerance. it should be a setting per platform." So the row
# below is exact for the host its measured-on line names, and any other host
# refuses to compare rather than fuzzing. The band was the bug's whole habitat —
# two per cent of 871,649 is 17,432 bytes of slack for a divergence documented
# at tens of bytes, and main drifted 376 bytes greener inside it with CI green
# the entire time.
#
# The stored figure is the runner's, read out of its own job log rather than
# measured here: a container on rustc 1.94.1 reads 864,274 against the runner's
# 864,300 on the same sources, and pasting the container's number in is exactly
# what the measured-on machinery exists to stop.
#
# WHAT IS COMPILED, from 2026-08-26: the library staged WITHOUT its test file.
# `kanso check lib/json` compiles lib/json's TEST file too, so every dependency
# the suite imports was entering the program this row measures — and a row that
# moves when a test file changes its imports answers a question nobody asked.
# scripts/gates/library_box.sh stages it. Ruled by Clay 2026-08-25 with the
# welfare rebuild: the library's compile golden measures the library.
# measured-on rustc=1.98.1
#
# 2026-09-03: the runner's rustc moved 1.98.0 -> 1.98.1 and this line moves
# with it. THE POINT RELEASE MOVED NOTHING. CI re-sat all three compile veins
# under 1.98.1 on family0x6-model0xcf, binary sha de5bfab22fbd, and every
# number came back identical to the one recorded under 1.98.0:
# compile_allocs 25,485, compile_peak_bytes 715,275, compile_instructions
# 41,831,767. Only the measured-on line changes.
#
# That is one datum against the granularity this file pins. measured_on.sh's
# own header says of rustc: "the upstream version only ... nothing here shows
# a point release moving a count, and pinning tighter than the evidence reds
# the gate on changes that are not changes." A patch bump reddening three
# gates while moving no number is exactly that shape. It is ONE observation
# and the pin is not loosened on it; the next point release is the second.
#
# 2026-08-30 (a dispatch group is a range): 763,868 -> 742,572, a fall of
# 21,296 or 2.8%. Banked. `infer`'s dispatch table held one heap `Vec<usize>`
# per (name, arity) for the length of the compile; the arms are one flat
# vector now and the table holds ranges into it. This row and the traffic row
# move together for once — the same change removed a per-call clone of those
# vectors, which `compile_allocs` sees and this cannot.
#
# 2026-08-30 (four vectors the front end rebuilt per iteration): 742,572 ->
# 743,564, a RISE of 992, or 0.13%. Banked as the price of a much larger fall
# on the traffic row: compile_allocs 44,920 -> 40,935, down 8.9%. Two of the
# four vectors are reused across iterations now — the `Vec<char>` a `Scanner`
# lexes a line with, and the `Vec<&str>` `callee_first` gathers a
# declaration's mentions into — and a reused buffer stays at the size of the
# largest thing it ever held where a fresh one dies with its iteration. 992
# bytes is one long source line and one large declaration.
#
# Rounds and visits do not move: nothing here changes what the compiler decides,
# only what it allocates deciding it.
#
# 2026-08-30 (four allocations the front end made per declaration): 743,564 ->
# 735,254, a fall of 8,310, or 1.1%. Banked, and one of the four did all of it:
# `callee_first` held a `Vec<usize>` per function declaration and holds one flat
# vector plus a start per declaration now, so four hundred headers become one.
# That also takes back the 992 bytes #1149's two pooled buffers cost, and 7,318
# more.
#
# The three borrowed-name pieces in the same change leave this row alone, which
# is right: a `String` built to answer a question and dropped is traffic rather
# than residency, and compile_allocs is the row that sees it.
#
# 2026-08-30 (the two tables the fixpoint kept per declaration): 735,254 ->
# 733,794, a fall of 1,460, or 0.2%, and it is two moves that nearly cancel.
# The reader bitset COSTS 6,096 bytes: n rows of ceil(n/64) u64 is 22,792 bytes
# for lib/json's four hundred declarations, held for the compile where the hash
# sets it replaces were sparse. Flattening `Inference::params` gives 7,556 back,
# because a `Vec<Set>` per declaration was a header and a padded block for one
# to three `u16`.
#
# Rounds and visits do not move, which is the check on the bitset: those two
# counters are exactly what a wake set that woke a different set would change.
#
# 2026-08-30 (a set nobody read): 733,794 -> 730,120, a fall of 3,674, or 0.5%.
# Banked, and it is one piece of the two in that change: `Resolver::used_globals`
# held a `String` per global mention for the length of a file's check, and
# nothing ever read the set. The reservation in `prune_unused_getters` beside it
# does not move this row, because that set is transient.
#
# 2026-08-30 (a word is a copy, not a re-encode): 730,120 -> 728,030, a fall of
# 2,090, or 0.29%. Banked, and it was not the point of the change — lex_word
# slices the line's &str on an ascii line instead of collecting &char, and a
# String built by to_string on a slice is allocated at the length it needs
# where one grown a character at a time overshoots. The first fall in this row
# since #1152. Both hosts read 728,030, as this row's two hosts always have.
# 2026-09-03 (a number's bytes are read once): visits 16,806 -> 17,169, a RISE
# of 363, or 2.2%, and rounds hold at 40. The json library's number scanner and

# that survives carries the mark as an argument and has more arms, so the front

# 2026-09-06 (an append of a slice reads the range in place): rounds 40 -> 42
