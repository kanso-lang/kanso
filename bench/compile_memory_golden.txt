# What the front end costs on a real library — checking lib/json, which is a
# thousand lines of kanso rather than the few hundred the emitted-code golden
# samples. Rounds and visits say how much work it decided to do; peak bytes
# says how much it had to keep while deciding.
#
# The five samples in compile_golden.txt hold 126 visits between them, and
# nothing a compiler change does moves that number. This one moves.
#
# Rounds and visits are counts of the compiler's own algorithm, so they are the
# same everywhere and CI diffs them exactly. Peak bytes is measured by the
# compiler's allocator and is a property of the host too — linux and macos
# disagree by 56 bytes on the same input — so the score reads this number and
# CI asserts only that reality has not drifted two per cent from it. Bucketing
# to kibibytes was tried and does not work: the two values straddle a boundary.
front_end_rounds=31
front_end_visits=26474
compile_peak_bytes=843429
# 2026-08-15: 819,217 to 843,429, up 24,212 bytes and 2.96%. rounds and visits
# do not move at all — the fixpoint does no extra work — so what this is, is
# the set of scalar-returning names the beat rules now consult, held once per
# compile. It buys a loop whose pushed element is a call the bracket it was
# being refused, and with it an arena that stays at one block instead of
# doubling with the round count.
