# What the front end costs on bench/compile_corpus, a fixed corpus that
# imports lib/json and the std modules the ruling names. Rounds and visits say
# how much work the front end decided to do; peak bytes says how much it had
# to keep while deciding. The samples in compile_golden.txt hold too few
# visits for a compiler change to move them; this row moves.
#
# Rounds and visits count the compiler's own algorithm, so they read the same
# on every host and the gate diffs them everywhere. They are not welfare
# terms: the objective weighs compile_peak_bytes, with compile_instructions
# and compile_allocs from their own goldens.
#
# Peak bytes is measured by the compiler's own allocator, so it belongs to the
# rustc that built it: a HashMap's growth schedule and a Vec's doubling are
# the standard library's. The row is exact for the host the measured-on line
# names, and any other host refuses to compare rather than reading against a
# band. Clay, 2026-08-24: "that shouldn't be a tolerance. it should be a
# setting per platform." On another host, take the runner's figure from CI's
# job log.
#
# A rise is a regression to explain and a fall is a win to bank: say which in
# design/compiler-log.md, which holds the history of every move, and move the
# welfare floor with --set in the same pull request.
