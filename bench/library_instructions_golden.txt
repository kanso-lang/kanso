# Retired instructions for `kanso check library_corpus/library_corpus.kso`,
# counted under callgrind and anchored at `kanso::main` inclusive.
#
# `kanso check` routes a file by its content. A file of definitions alone is a
# library and goes through compile_library, which merges the dependency
# program and runs its own whole-program check. `kanso test` takes that path
# on every run, and so does `kanso check` on most files in the tree.
# bench/compile_instructions_golden.txt counts a directory, which is a module,
# and bench/entry_instructions_golden.txt counts an entry.
#
# Not to be confused with bench/compile_libraries_golden.txt, which lists the
# shared objects the compiler links against.
#
# The rules this row shares with the module row are stated in that row's
# header: the seedless hash, the box at a fixed path, one row holding one
# value, the toolchain on the last line, the row taken from CI.
#
# EXCLUDED, because it cannot be normalized: `std::io::stdio::_print`
# inclusive, the one line `kanso check` prints when it finishes. Its cost
# moves with the binary's layout. The corpus is a single file, so no
# directory is read and the module row's second exclusion does not arise. The
# gate subtracts the subtree and prints it as a notice.
#
# A rise is a regression to explain and a fall is a win to bank: say which in
# design/compiler-log.md, which holds the history of every move.
