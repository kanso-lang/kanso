# How much machine code each benchmark carries: the .text section, measured on
# the linux runner before anything runs. Deterministic for a given source and
# toolchain, and it is the code itself.
#
# The allocation counters cannot see this dimension, and neither can the
# emitted-line count, which also counts functions the linker drops. A decode
# regression once accrued over eleven days with every allocation counter
# byte-identical, and code growth carried a measured 17% of it. The welfare
# objective does not weigh this vein (tests/the_objective_does_not_weigh_
# machine_code_size.rs); it is gated here on its own.
#
# Watched, not frozen. A rise is a regression to explain and a fall is a win
# to bank; a toolchain bump moves every row at once and is regenerated in one
# go, with a sentence in design/compiler-log.md saying so. That log holds the
# history of every move.
#
# .text is what the toolchain made of the source, so the rows belong to the
# compiler that emitted them, and the gate compares the clang on the last line
# of this header with the one it is running under before it measures. The
# upstream version is pinned and the package revision is not: the release
# selects codegen, and nothing here shows a revision moving a byte.
# measured-on clang=19.1.1
