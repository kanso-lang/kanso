# How much machine code each benchmark carries, the .text section measured on
# the linux runner before anything runs. Deterministic for a given source and
# toolchain, and blind to nothing that matters: this is the code itself.
#
# It exists because the dimension that carried a measured 17% of the 7.6%
# decode regression had no gate at all. Every allocation counter was
# byte-identical across the eleven days it accrued. The emitted-line count did
# move, but a fifth of those lines turned out to be functions the linker was
# already dropping, so it moves for reasons that never reach the machine. What
# grew was the code: 54,708 to 79,192 bytes on the measuring host over that
# window, and padding an old build up to that size with functions it never
# calls costs 1.6% of decode time on its own.
#
# Watched, not frozen. A rise is a regression to explain and a fall is a win to
# bank; a toolchain bump moves every row at once and is regenerated in one go,
# with a sentence in design/compiler-log.md saying so. A number that changes
# without a sentence is the thing to catch.
#
# Which host, made checkable. .text is what the toolchain made of the source,
# so the row belongs to the compiler that emitted it, and the gate compares
# this line against the clang it is running under before it measures anything.
# The upstream version is pinned and the package revision is not: what selects
# codegen is the release, and nothing here shows a revision moving a byte.
# measured-on clang=18.1.3
#
# 2026-08-12: encodebench 102,642 to 101,778, oneshot 101,826 to 100,962,
# basket 93,186 to 92,322 — the same 864 bytes off each — and jsonbench
# unmoved. A fall, and the emitted IR is byte-identical to the previous
# revision for all four, so none of it comes from the compiler. It is the
# runtime: division and modulo used to raise, building a string and carrying an
# origin pointer at each of five call sites, and now they answer a value from
# one argument. jsonbench holds still because it links neither `k_div` nor
# `k_mod` — it decodes and prints, and the linker drops what it cannot reach.
# The other three link both, which is why they move together and by the same
# amount.
#
# 2026-08-12 (later): basket 92,322 to 92,354, the other three unmoved. A rise
# of 32 bytes, and it is the compare-and-branch that stops `k_b_str_builder`
# re-seeding a header that still has room. That guard takes an accumulator
# handed through one intermediate function from 752,908,406 instructions to
# 16,519,843 at eight thousand appends, and takes book_panels --write from
# killed to finished. Thirty-two bytes.
#
# 2026-08-12 (later still): basket 92,354 back to 92,322, the same 32 bytes.
# The guard is withdrawn — spare capacity is not sole ownership, and the write
# path it was said to rescue is the one it broke, to 88 GB and a SIGKILL. The
# claim above about book_panels --write is wrong in both directions and the
# instruction figure was never re-measured against the shape that matters.
# 2026-08-13: jsonbench 83,714 to 83,794, encodebench 101,778 to 101,874, oneshot
# 100,962 to 101,042, basket 92,322 to 92,690. A rise everywhere, and it is the
# carry learning to keep a slot: the flag array, the two branches that skip a
# kept slot in `k_beat_iter_carry`, and the promotion that moves a kept header
# off the arena. Every program linking the beat carry pays for them; basket pays
# most because it carries most. Nothing else moves — the allocation counters for
# 2026-08-13: every benchmark shrinks, by 2,112 to 2,416 bytes. k_str_alloc is
# made inline, and the call sequences it removes at forty-eight sites are larger
# than the body they duplicate — a few stores, a branch on the stats flag, and
# lengths the optimiser can fold once the body is in front of it.
# 2026-08-20 (last): jsonbench 78,626 to 79,922 and oneshot 95,858 to
# 97,154 — 1,296 bytes each, the only two rows that link the JSON decoder.
# It is the surrogate-pair machinery: five functions joining `\u` halves
# where one function refused them. 1.6% on jsonbench, bought outright — a
# decoder that rejects every ensure_ascii astral character is not smaller,
# it is wrong.
# 2026-08-20 (thunk walk): every row rises by exactly 544 bytes — the
# thunk-aware evacuation in the runtime object every binary links. What it
# buys is correctness: an unforced thunk crossing a cohort close used to
# read reused memory when finally walked.
# 2026-08-20 (shorthands): jsonbench falls 704 bytes and oneshot 656 —
# the dead hex trio leaving the linker's output — while the two new
# escape arms ride inside the existing jump table for less than the
# deletion returns. The other six rows are untouched.
# 2026-08-20 (bisimulation): every row rises by exactly 48 bytes — the
# thunk-pair arm of k_eq_rec answering equal where it used to die, in the
# runtime object every binary links — escapebench alone unmoved, and
# pendbench FALLS 448:
# its tail-position ifs now force through the shared maybe_force path
# instead of each carrying its own cold-call plumbing.
# 2026-08-20 (pendbench): the corpus gains its lazy row at 73,906 bytes —
# a new binary, not a change to any existing one; the seven old rows are
# untouched.
# 2026-08-13 (last): +16 bytes on every binary. net/port adds k_b_net_port to
# the runtime object, and every program links the runtime whether or not it
# opens a socket.
# 2026-08-14: a fifth row. widebench decodes a flat array of twenty thousand
# floats and streams it back through a chained io bind, which is how kq prints
# a top-level array. No existing row moves — nothing about the other four
# changed — so this is the corpus growing rather than the code.
# 2026-08-14: basket rises 640 bytes for the getter group that forces before it
# reads, and 176 more for the join that forces before it sizes. basket is the
# only one of the original four that reaches either; widebench's row was
# measured before both and is the runner's to confirm.
# 2026-08-14: basket rises 640 bytes. A getter group that matched nothing now
# forces the value and reads the field rather than printing and exiting, so the
# group returns where it used to end. basket is the only one of the original
# four that links such a group; widebench's row is the runner's to confirm.
# 2026-08-14: +704 bytes on every binary, the same figure five times, because
# every program links the runtime whether or not it prints a wide array. It is
# the memo that stops k_interior_survives rescanning a list once per element:
# a pointer map, its lookup, and the outermost-mark test.
# 2026-08-14 (later): every binary falls 4,976 bytes. The carry learns to
# tenure a value that has lived a lap, and the two copy walks are rewritten
# around it: one function each rather than a wrapper and a body, with the
# tenure flag set where a lived-a-lap node is found and never unset within an
# evacuation. The flag removes a save and a restore from every node of the
# hottest recursion in the runtime, and the code that goes with it is smaller
# than what the split cost.
# 2026-08-14 (last): 48 bytes on three binaries and 96 on basket; jsonbench
# does not move. The strict index forces the element it hands back, so `!`
# costs what it has always claimed to mean.
# 2026-08-15: +64 bytes on every binary, the same figure five times. Under
# KANSO_COUNTERS the runtime now installs a SIGUSR1 handler that dumps the
# counters where the program stands, so a run that has to be killed can still
# be read. Every program links the runtime, so every program carries the
# handler and the registration whether or not it is ever signalled. The
# counters used to print at exit only, which meant a program that never
# reached exit — the shape this was built to diagnose — printed nothing at
# all, and forty-five seconds of a hang looked identical to a healthy short
# run.
# 2026-08-15: a sixth row. deepbench carries a short accumulator across an io
# bind whose lambda captures the structure it built, which is what a simulator
# folding over trials does and what the other five never did. No existing row
# moves — this is the corpus growing rather than the code.
# 2026-08-15: 128 bytes on four binaries, 112 on encodebench, 80 on
# deepbench. That is the size test, the drift test and the two globals they
# read, linked into every program whether or not it ever carries a small step.
# 2026-08-15: 112 bytes on jsonbench, 96 on encodebench and oneshot, 128 on
# basket, 96 on widebench. Two counters watching malloc-backed accumulator
# storage: the globals, the increment where such a buffer is taken and the
# decrement where one is released. Every program links the runtime, so every
# program carries them whether or not it ever grows an accumulator that
# outlives its beat.
# 2026-08-15: +1,712 bytes on jsonbench, +1,696 on encodebench and oneshot,
# +1,792 on basket, +1,712 on widebench, and deepbench does not move at all.
# The registry that frees escaped accumulator storage: three arrays, the push
# that grows one, the flush and the migrate, and the beat-stack walk that
# decides which depth owns a buffer. Every program links the runtime, so every
# program carries it whether or not it grows an accumulator past its beat.
#
# About half of that is bought deliberately. The first shape was 848 bytes and
# cost 0.68% of the decoder's instructions on a program whose
# perm_peak_bytes is zero; splitting the empty test inline and putting a hot
# flag in front of the cold array doubled the code and took the instruction
# cost to 0.35%. deepbench holds at 61,010 across all three shapes — it links
# least of the runtime, and the section's alignment absorbs what it does link.
# 2026-08-15: a seventh row, and the smallest binary in the file by a wide
# margin — escapebench links no decoder, no encoder and no io beyond one
# write, so what it carries is the runtime and the loop. No existing row moves.
# 2026-08-15: -144 bytes on every binary, the same figure seven times. The
# memo's unconditional path goes away and a length test takes its place.
# 2026-08-15: basket +144 bytes and escapebench +64; the other five do not
# move. A cluster of groups in one tail cycle may now be entered by a plain
# call and bracketed, and these two are the benchmarks holding such a cycle —
# the push and pop around the entry, and the rewind in the loop, are code
# their binaries did not carry before.
# 2026-08-17: every row rises — jsonbench +464, encodebench +528, oneshot
# +464, basket +320, widebench +528, deepbench +480, escapebench +448. The
# render path gains a thunk arm: a forced cell is pushed before the walk
# descends and popped after, so a knot that closes through a cell prints
# `<cycle>` rather than walking a ring forever. Every program links the
# renderer, so every program carries the test.
#
# The first version of this entry was WRONG and said basket did not move at
# all. Its numbers came from a run whose head predated the render guard —
# a PR merge commit one push behind — so they measured the emitter change
# without the runtime one. Read the run whose head sha IS the commit being
# pinned; a green-looking older run for the same branch is not that.
# 2026-08-17 (later): +80 on five rows, +16 on jsonbench, +112 on
# escapebench. Rendering forces what it prints, and a list or a map now goes
# on the render path the way a record already did — the scan, the push and
# the pop, linked into every program because every program links the
# renderer. jsonbench moves least because it renders no container the guard
# has to walk twice.
# 2026-08-17 (last): five rows fall — jsonbench -2,320, encodebench -2,176,
# oneshot -2,352, basket -2,160, widebench -2,352. deepbench and escapebench
# hold. A module reached by two import paths is one module now, and what that
# changes in the emitted code is the name: a dependency of a dependency stops
# compounding the entry module's prefix, so `jsonbench/list/bounded` is
# `list/bounded`. escapebench is the one entry whose inner module imports
# nothing, and it is the row that does not move by any measure.
#
# What produces the size of the falls is the cohort pop. Counting calls to
# k_cohort_pop in the emitted IR against main, per row: jsonbench 2 to 0,
# encodebench 3 to 0, oneshot 4 to 0, basket 3 to 0, widebench 3 to 0,
# deepbench 0 to 0, escapebench 1 to 1. The five that lose every pop are the
# five that fall, and the two that keep their count are the two that hold —
# no exceptions across the corpus. With no call left, the linker drops
# k_cohort_pop and what only it reaches, which is machine code this gate can
# see and the emitted-line count cannot.
#
# Those pops were reclaiming nothing. Every allocation counter is
# byte-identical across this change, the lazy tier's mem goldens pass
# unchanged, and escapebench — the one row whose storage escapes its beat,
# and whose perm_peak_bytes this file elsewhere records falling to 10,272 —
# is the row that KEEPS its pop.
#
# 2026-08-18: the entry above is WRONG about the cause and is withdrawn. The
# falls are real and the rows are right. What produced them is not pops that
# were reclaiming nothing — it is cohort ENTRY no longer being detected.
# src/codegen.rs decides one by asking whether the callee's module name
# extends the caller's by a segment, which is the compounded route spelling
# this change removes. Instrumented on jsonbench: main takes that branch 13
# times, twelve of them `jsonbench` into `jsonbench/text`; this compiler takes
# it once. escapebench keeps its pop because its one hit has an empty caller,
# which the test still admits — not because it is the row that collects.
#
# These numbers therefore describe a compiler with cohort entry switched off.
# They are not a baseline to keep, and they are pinned here only so the gate
# has something to diff while the predicate is rebuilt.
# 2026-08-19: every row rises by exactly 208 bytes — jsonbench 77,794 to
# 78,002 and the other five the same 208, between 0.2% and 0.3% each. That
# uniformity is the whole reading: what grew is `k_eq_rec` in the runtime
# object, which every binary links and none of these benchmarks calls more or

# 2026-08-20: every row rises, six of them by exactly 592 bytes and

# What it buys is a loop written with `>>` that runs at all — four hundred

# 2026-08-20 (later): +32 bytes on six rows and deepbench unmoved. Three
# counter sites in the runtime object every binary links: the malloc counted

# 2026-08-23: three rows rise and five hold. encodebench and widebench take
# 16 bytes each, escapebench 32, and jsonbench, oneshot, basket, deepbench and

#
# The gavel of the same date took the startup freeze out: `k_caf_init` used to
# build every knotted constant before main, and each constant now seeds and

#
# The decoder holds still, which is the row that matters most here: jsonbench
# links no knotted constant, so the hottest path in the project is untouched.
# What the branch buys is on the other veins — the mem corpus fixture for an

# 2026-08-26: every binary grows, and by a different amount each — jsonbench
# +544, encodebench +624, oneshot +592, basket +256, widebench +624, deepbench

# 2026-08-26: every benchmark grew — jsonbench 80,450 -> 80,738, and 32 to 128
# bytes elsewhere. The register-returnable construction stopped bailing on its
