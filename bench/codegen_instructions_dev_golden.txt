# Retired instructions for a whole `kanso build` of bench/codegen_corpus on the
# development tier: the build a programmer runs while working.
#
# The compile rows stop before codegen: compile_instructions,
# entry_instructions and library_instructions count `kanso check`. This row
# counts what a build adds, as the child tree under `--trace-children`: the
# clang driver, the convention probe's clang, `clang -cc1`, the linker and the
# linker's own child, their summary lines summed. kanso's own process is
# excluded, because it waits for clang and a loop that waits is the
# scheduler's to size; emit_instructions counts the emitter's frame inside it.
#
# Two tiers, ruled 2026-09-16: the two builds are different programs with
# different jobs, and one number over both would let one pay for the other.
#
# Normalized before it is counted. The package is staged in a box
# (scripts/gates/codegen_box.sh) because the count moves with the length of
# the directory the compiler runs in, and the gate refuses a tree of fewer
# than four processes. Every run is `env -i` with the same variables, because a
# child inherits the environment block on its stack and its size moves the
# count.
#
# Most of the tree is the C toolchain, so the row belongs to clang as well as
# glibc and rustc, and the measured-on line names all three. Only CI's
# numbers are recorded.
#
# A rise is a regression to explain and a fall is a win to bank: say which in
# design/compiler-log.md, which holds the history of every move.
# measured-on glibc=2.39-0ubuntu8.9 clang=19.1.1 rustc=1.98.1
