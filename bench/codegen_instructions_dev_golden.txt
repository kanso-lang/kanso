# Retired instructions for a whole `kanso build` of bench/codegen_corpus on the
# development tier: the build a programmer runs while working, where the time
# between a keystroke and an answer is the whole of what matters.
#
# THE COMPILE ROWS STOP BEFORE CODEGEN. compile_instructions, entry_instructions
# and library_instructions all count `kanso check`, which answers whether a
# program is well formed and then stops. Everything after that — the emitter
# writing LLVM IR, the clang driver, clang -cc1, the linker and the linker's own
# child — was uncounted, and it is the larger half of what a build costs. This
# row counts the whole tree: five processes under `--trace-children`, their
# summary lines summed.
#
# WHY TWO TIERS. The two builds are different programs with different jobs, and
# a single number over both would let one pay for the other. Ruled 2026-09-16.
#
# MEASURED IN A BOX, for the reason the other compile rows are: the count moves
# with the length of the directory the compiler runs in. scripts/gates/
# codegen_box.sh stages the package one level down, as pkg/codegen_corpus, so
# that `kanso build` does not find a directory beside its argument's stem and
# refuse — a refusal that still emits the IR first, so it looks like a build
# and counts two processes instead of five. The gate refuses a tree shorter
# than four.
#
# THIS ROW DEPENDS ON CLANG, which the other compile rows do not: most of the
# tree is the C toolchain, so the measured-on line names it beside glibc and
# rustc.
#
# 2026-09-17, the first sitting (kanso#1470). CI's reading, taken on the
# runner because a row this gate pins may only ever be counted there: this
# container read 1,450,337,132, which is a different clang and a different
# machine and is not comparable. Five processes, and the second reading in the
# same job agreed with the first.
# measured-on glibc=2.39-0ubuntu8.9 clang=19.1.1 rustc=1.98.1
#
# 2026-09-17 (kanso#1470): codegen_instructions_dev 9,280,351,472 -> 1,003,426,243.
# The old value is not a regression this fixes; it is what the row read before the
# gate warmed the runtime.c cache under the measurement's own environment. That
# reading paid for compiling runtime.c and this one does not, and the gate's
# header records how the difference was found. Counted twice in one job and
# byte-identical both times.
#
# 2026-09-17, later: THE ROW IS THE CHILD TREE NOW, and the value below is a
# whole-tree reading, so it will disagree by kanso's own process -- about
# 425 million -- on the next sitting and that sitting writes it. kanso's own
# process is excluded because it waits for clang, and the loop that waits is
# the scheduler's to size; the gate's header carries the measurement behind
# that. The exclusion is not a change to what codegen costs, only to which
# processes the row calls codegen.
#
# 2026-09-17, CI's first sitting, which is the measurement this row was opened
# for. 596,161,187, and `codegen_dev_again` read 596,161,187 -- the two
# readings in one job agree to the instruction.
# #
# THAT AGREEMENT IS THE POINT. The row's first shape counted the WHOLE process
# tree and two readings in one job differed by 3,105 while every child was
# byte-identical; the parent sits in a wait loop for clang and the linker, and
# what that loop costs is the box's scheduling. Excluding kanso's own process
# under the 2026-09-15 rule is what made the row reproducible, and this sitting
# is the evidence it worked.
# #
# The container's placeholder read 1,003,426,243, which was the pre-exclusion
# shape and is not comparable to this.
# 2026-09-17, kanso#1493 on the tree merged with main 5e256ce0, CI's sitting.
# 596,161,187 -> 596,161,166, a FALL of 21 -- 35 parts per billion. This row
# excludes kanso's own process and counts the C toolchain, so twenty-one
# instructions is clang and ld landing marginally differently on IR they
# compiled the same way. A second count in the same job read 596,161,166.
#
# kanso's own process, which the row excludes and the gate prints as a notice,
# is where this branch shows: codegen_dev_kanso_excluded=406,043,465 against
# main's 407,173,801, a fall of 1,130,336. A build pays the same start-up a
# run does.
#
# 2026-09-18, kanso#1507 on the tree merged with main, CI's sitting. 596,161,166 ->
# 596,159,774, a FALL of 1,392 (-0.00023%). LAYOUT. This branch adds a
# `match std::env::var("KANSO_LTO_JOBS")` to `release_clang` in src/main.rs and
# `KANSO_LTO_JOBS=1` to three `env -i` lines in a gate script. src/main.rs is
# the compiler, so its bytes and the layout under them move, and every row that
# runs the compiler moves with them. Seven rows moved here and all seven are
# under five ten-thousandths of a per cent, with mixed signs -- which is what a
# shifted binary looks like and not what work looks like.
#
# 2026-09-18, THE GATE NOW CLEARS ITS OUTPUT PATH BEFORE EVERY BUILD, so this
# row measures a different thing and the value below is the OLD one, left in
# place for CI to move. `ld` reads whatever is already at `-o`, and what it
# finds there changes the count. On the container, one binary, one corpus, the
# same `ld` command each time, varying only the output path's state:
#
#     absent            5,163,341,031   (twice, to the instruction)
#     an empty file     5,163,341,036   (twice, +5)
#     100 bytes         5,163,343,385
#     5 MB              5,163,343,385
#     the real binary   5,163,343,385   (+2,354 over absent)
#
# Three groups, each internally identical, and size stops mattering once the
# file is non-empty. The gate read the third group by accident -- the warm-up
# left its binary at `-o` -- and now reads the first by construction. THIS IS
# A MEASUREMENT CHANGE AND NOT A COMPILER SAVING: nothing about the compiler
# moved, and the fall this produces is the gate no longer counting `ld`'s
# inspection of a file left over from the previous build.
