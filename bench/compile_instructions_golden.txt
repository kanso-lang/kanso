# Retired instructions for `kanso check lib/json`, counted under callgrind.
#
# bench/instructions_golden.txt counts the benchmarks, which are the programs
# the compiler PRODUCES. This counts the compiler. Until 2026-08-24 nothing
# did, and on that day a change took the front end from 90.9 million retired
# instructions to 67.2 million with every gate in the tree reporting nothing:
# compile_allocs identical at 87,824, rounds identical at 40, visits identical
# at 17,786, and compile_peak_bytes moving twelve thousand bytes inside a
# thirty-five thousand byte band. A quarter of the work went away in silence,
# and a quarter coming back would have been just as quiet.
#
# THIS ROW COULD NOT HAVE EXISTED BEFORE THAT CHANGE. std's default hasher
# carries a per-process random key, and the key moves the probe sequences and
# moves where the rehashes land, so the count was not a repeatable quantity.
# Same binary, same sources, same directory, empty environment:
#
#   default hasher   90,704,760   90,676,800
#   seedless hash    66,961,255   66,961,255   66,961,255
#
# Forty thousand instructions of spread against nothing to explain it. The
# compiler hashes its own maps with a seedless hash now, and three runs give
# the same digits.
#
# MEASURED IN A BOX. The count moves with the length of the directory the
# compiler runs in — 5,613 instructions across 35 characters, about 160 each,
# because the absolute path is copied and walked. Read from the checkout this
# row would pin the clone, which is the reason compile_alloc_bytes is absent
# from its own golden rather than pinned in it. The gate copies lib/ to a
# fixed path and compiles from there, so two clones at different depths agree
# to the digit.
#
# The row belongs to the toolchain that built the binary and to the libc that
# serves its malloc and its memcpy, so it names both and
# scripts/gates/measured_on.sh refuses to read it anywhere else.
#
# A rise is a regression to explain and a fall is a win to bank. Movement is
# fine; silence is not.
#
# The row is the runner's, copied out of the job log the way this file's own
# rule requires. On the gate's first run the container read 66,968,333 against
# the runner's 66,450,587 — half a per cent apart on the same sources in the
# same box, which is the provenance line earning its place before a bad paste
# rather than after one.
#
# A figure quoted elsewhere from a plain `kanso check lib/json` in a checkout
# will differ slightly from this row, and should. This one is measured in the
# box with the environment emptied; that one is not.
#
# WHAT IS COMPILED, from 2026-08-26: the library staged WITHOUT its test file.
# `kanso check lib/json` compiles lib/json's TEST file too, so every dependency
# the suite imports was entering the program this row measures — and a row that
# moves when a test file changes its imports answers a question nobody asked.
# scripts/gates/library_box.sh stages it. Ruled by Clay 2026-08-25 with the
# welfare rebuild: the library's compile golden measures the library.
# measured-on glibc=2.39-0ubuntu8.8 rustc=1.98.0
#
# 2026-08-26: 56,849,156 -> 57,490,077, a rise of 640,921 (1.13%). The
# own-origin rule is dispatch semantics, so the front end now carries a
# package name on every raise site and asks, at every arm that could match its
# own hako's err, whether it may. Some of the rise is that work and some is
# layout: `src/runtime.c` is `include_str!`'d into the compiler and grew, and
# the entry above this one records the same edit measuring +664, +393 and
# -6,763 on three sittings of one diff. The two are not separable from this
# row alone. What is separable is the direction of the counters that do only
# measure the front end's work, and all three of those FELL: visits 16,818 to
# 16,806, allocations 62,110 to 61,981, peak 825,664 to 822,004, because the
# pub self-seed went and `lib/json` shed `must` and `defect`.
#
# 2026-08-27: 57,492,931 -> 57,493,961, a rise of 1,030 (0.0018%). A file
# module could be imported and could never import: `load_dependencies` was
# handed the module's own path as the base for resolving its imports, and for
# a file module that path is the FILE, so `./sibling` was looked for under
# `a.kso/`. The fix asks `dir.is_file()` once per module load, and this row is
# the handful of stat calls that costs. The counters that measure only the
# front end's work do not move at all: allocations 61,981 and peak 822,004,
# both identical.
#
# 2026-08-27: 57,493,961 -> 57,486,466, a fall of 7,495 (0.013%), banked.
# `check_unused_private` is deleted. Its two loops walked every declared
# function and every declared type asking whether the name begins with an
# underscore, which the lexer has refused since leading underscores were
# retired — so the walk ran on every compile and could never answer yes. What
# went away is the walk. The counters that measure only the front end's work do
# not move: allocations 61,981 and peak 822,004, both identical, which is what
# a deletion of work that allocates nothing should read as.
#
# 2026-08-27: 57,486,466 -> 57,486,215, a fall of 251 (0.0004%), banked. The
# change is two match arms in `call_builtin` for `args` and `stdin`, and
# `call_builtin` is the INTERPRETER's door — `kanso check lib/json` never
# enters it. So this is layout, not front-end work, the same way the +167 of
# 2026-08-26 was: the compiler's own binary moved under an edit to a function
# the measured path does not call. The counters that measure only the front
# end's work are identical: allocations 61,981 and peak 822,004. A fall this
# small with an untouched call graph is banked as layout and claimed as
# nothing else.
#
# 2026-08-27: 57,486,215 -> 57,488,169, a rise of 1,954 (0.0034%). Layout, and
# provably so this time rather than by resemblance. The change is one match on
# `std::io::ErrorKind` inside `read_file_text`, and `read_file_text` has
# exactly one caller: the executor's `read_file`, an EFFECT. `kanso check
# lib/json` compiles a library and runs no program, so it cannot reach that
# function at all. The counters that do measure the front end's work are
# identical — allocations 61,981 and peak 822,004 — and the profile's own rows
# moved the way layout moves them: `__memcmp_avx2_movbe` fell 327 while the
# total rose. Third movement of this vein in two days with an untouched call
# graph: +167, -251, +1,954.
#
# 2026-08-27: 57,488,169 -> 57,489,912, a rise of 1,743 (0.003%). REAL WORK,
# and the first of today's four moves that is. The other three were layout —
# each edited a function `kanso check lib/json` cannot reach — and the reflex
# by the fourth was to reach for the same reading. It does not hold here.
# `resolve_expr`'s walk over block and build bodies runs on every compile, and
# it gained an `enumerate` and one index comparison per statement, which is
# what these instructions are.
#
# What they buy: an effect line written in a `build` body used to be neither
# run nor complained about. Three `io/write` lines ran the last and lost the
# other two, in silence, on both engines. That walk had no unused-expression
# check at all. Allocations and peak do not move (61,981 and 822,004) because
# an index comparison allocates nothing, so the counters agreeing here is
# evidence about the SHAPE of the work rather than evidence that there is none.
