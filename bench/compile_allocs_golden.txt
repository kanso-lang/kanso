# What the front end ALLOCATES on lib/json, beside what it keeps.
#
# bench/compile_memory_golden.txt holds the work the compiler decided to do —
# rounds and visits — and the peak it held while deciding. Neither can see the
# traffic: a pass that allocates a String per identifier occurrence and one
# that borrows the program's names finish with the same rounds, the same
# visits and the same peak, because the strings are transient. That pass was
# rewritten on 2026-08-24 for a quarter off its time, and every gate in the
# tree reported nothing.
#
# The row below is that dimension. It comes off the counting allocator in
# src/main.rs, which has printed it since it went in and which nothing has
# ever pinned.
#
# The allocator prints a second counter, compile_alloc_bytes, and that one is
# deliberately absent. It measures the checkout path. Five directory lengths,
# same tree, same binary — read against the compiler as it stood on
# 2026-08-24, before the child walk stopped building vectors, so these are the
# shape rather than today's totals:
#
#   16 chars  7942065        29 chars  7942091
#   17 chars  7942067        49 chars  7942131
#   21 chars  7942075
#
# which is 7942033 plus twice the length of the directory the compiler ran in,
# exactly, at every point — two allocations hold the absolute path. A row that
# moves when the repository is cloned somewhere else is pinning the clone. The
# dimension it was wanted for is covered on both sides: compile_allocs holds
# the traffic and compile_peak_bytes holds the residency.
#
# The count belongs to the rustc that built the binary, because a good part of
# it is the standard library's — a HashMap's growth schedule, a Vec's
# doubling, a String's spare. So the file names its toolchain and
# scripts/gates/measured_on.sh refuses to read the row anywhere else, the same
# arrangement the instructions and machine-code veins have. On the two
# toolchains measured so far it has not moved: 85788 under rustc 1.94.1 and
# under 1.98.0 alike, as 87290, 87824, 91185 and 148073 were before it. Two versions is
# evidence rather than a guarantee, so the provenance line stays. A bump that
# does move the row is a number to regenerate and a sentence to write.
#
# A rise is a regression to explain and a fall is a win to bank. Movement is
# fine; silence is not.
#
# WHAT IS COMPILED, from 2026-08-26: the library staged WITHOUT its test file.
# `kanso check lib/json` compiles lib/json's TEST file too, so every dependency
# the suite imports was entering the program this row measures — and a row that
# moves when a test file changes its imports answers a question nobody asked.
# scripts/gates/library_box.sh stages it. Ruled by Clay 2026-08-25 with the
# welfare rebuild: the library's compile golden measures the library.
# measured-on rustc=1.98.0
#
# 2026-08-29 (the three chain words): 61,981 -> 61,974, a fall of 7. Banked
# rather than explained in detail: the front end gained three names in
# BUILTINS and three in AMBIENT and lost nothing, so a fall of seven
# allocations out of sixty-two thousand is layout, in the same family as the
# entries in the instructions golden beside it.
# 2026-08-30 (a call's argument sets on the stack): 61,974 -> 57,430, a fall of
# 4,544, or 7.3%. Banked. `eval_call` collected a call's argument sets into a
# `Vec<Set>`, and `Set` is a `u16`: dhat's map put that one line at 8,309 of
# the front end's blocks, the largest single line in it, holding two, four or
# six bytes apiece. Eight fit in sixteen bytes of stack and higher arities
# still spill. `compile_peak_bytes` does not move, because these blocks died
# when the call was inferred and were never at the high water mark — which is
# why nothing but the map could see them.
#
# 2026-08-30 (a dispatch group is a range): 57,430 -> 54,747, a fall of 2,683,
# or 4.7%. Banked. `eval_call` cloned its dispatch group's `Vec<usize>` on
# every call it inferred, to release the borrow on `ctx` before the loop below
# takes it mutably. A group is a half-open range into one flat vector now, and
# a range copies. `compile_peak_bytes` falls 21,296 with it, because the table
# it cloned from was itself one heap vector per (name, arity).
#
# 2026-08-30 (four lookup keys the program holds): 54,747 -> 50,528, a fall of
# 4,219, or 7.7%. Banked. `inline.rs` built a `String` in order to look one up,
# in three places — the alias fixpoint's keys and values, and the callee at
# every `App` node the rewrite walked — and kept a private child walk that
# returned a fresh vector per node. All four now borrow from the program or
# hand children to a callback. `check.rs` had worked around the third of these
# by building a borrowed view of the map; the producer borrows now, so the
# view is gone too.
