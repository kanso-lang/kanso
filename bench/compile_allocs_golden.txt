# What the front end allocates on bench/compile_corpus, beside what it keeps.
#
# bench/compile_memory_golden.txt holds the work the compiler decided to do
# (rounds and visits) and the peak it held while deciding. Neither sees the
# traffic: a pass that allocates a String per identifier and one that borrows
# the program's names finish with the same rounds, visits and peak, because
# the strings are transient. This row is that dimension, off the counting
# allocator in src/main.rs.
#
# The allocator prints a second counter, compile_alloc_bytes, and it is left
# out on purpose: it reads the checkout's path, at two bytes per character of
# the directory the compiler ran in, so a row of it would pin the clone. The
# traffic is here and the residency is compile_peak_bytes.
#
# The count belongs to the rustc that built the binary, because much of it is
# the standard library's (a HashMap's growth schedule, a Vec's doubling, a
# String's spare). The file names its toolchain, and
# scripts/gates/measured_on.sh refuses to read the row anywhere else.
#
# No blank line may stand outside a comment in this file: compile_allocs.sh
# compares it to its own output through `grep -v '^#'` and a diff, so a blank
# line fails the gate on a row that agrees. Separate notes with a bare `#`.
#
# A rise is a regression to explain and a fall is a win to bank: say which in
# design/compiler-log.md, which holds the history of every move.
# measured-on rustc=1.98.1
